# Dearr --- Design System & UX Specification

**Version:** V1\
**Platform:** Mobile-first e-commerce experience\
**Product:** Dearr\
**Related Documents:** `Dearr_PRD.md`, `Dearr_TRD.md`,
`Dearr_APPFLOW.md`

> **Note:** This document uses the color and typography values supplied
> in the current design brief as the design-system source of truth for
> this V1. Where the earlier brand reference and this brief differ, the
> current brief takes priority for implementation until the brand system
> is formally revised.

## 1. Design Principles

### 1.1 Warm and Joyful

Dearr should feel friendly, affectionate, and gift-oriented without
becoming visually noisy. Use soft surfaces, rounded cards, cheerful
accents, and the brand's expressive typography selectively.

### 1.2 Product First

Product photography, product name, price, discount, and primary actions
should receive the strongest visual attention. Decorative elements
should never compete with shopping information.

### 1.3 One Clear Action

Every important screen should have one obvious primary action. Secondary
actions should remain visually quieter.

### 1.4 Mobile First

Design starts from the smallest supported phone width and scales upward.
Controls should be comfortable for thumbs, content should remain
readable, and the main shopping journey should work without horizontal
scrolling.

### 1.5 Consistent and Calm

Use a small number of colors, a predictable spacing scale, reusable
components, and consistent interaction patterns across customer and
admin areas.

### 2.3 Color Usage Rules

-   Use **Primary `#A2CB8B`** for the main action, not every clickable
    element.
-   Use **Secondary `#FFCB56`** mainly for highlights and promotional
    emphasis.
-   Avoid large areas of saturated color behind long text.
-   Use white surfaces for product cards and forms.
-   Error and warning text should always be paired with an icon or clear
    message, not color alone.
-   Maintain readable text contrast against every surface.

## 3. Typography

### 3.1 Font Families

  -----------------------------------------------------------------------
  Font                    Role                    Usage
  ----------------------- ----------------------- -----------------------
  **Telma**               Brand/display font      Logo-adjacent
                                                  messaging, hero
                                                  headlines, campaign
                                                  headings, special
                                                  promotional text

  **Inter**               UI/body font            Product names, body
                                                  text, buttons, forms,
                                                  navigation, prices,
                                                  admin dashboard
  -----------------------------------------------------------------------

**Font rule:** Telma is expressive and should be used selectively. Inter
carries the majority of functional information for readability.

### 3.2 Type Scale

  ------------------------------------------------------------------------------------
  Style        Font                Size        Weight   Line Height Usage
  ------------ ---------- ------------- ------------- ------------- ------------------
  Display      Telma               32px           700          38px Main hero headline

  H1           Telma               28px           700          34px Main page heading

  H2           Telma               24px           700          30px Section heading

  H3           Inter               20px           700          26px Product/category
                                                                    section heading

  Body Large   Inter               17px           400          25px Intro/supporting

  Body Medium  Inter               15px           500          22px Product names, UI
                                                                    labels

  Caption      Inter               13px           400          18px Helper text,
                                                                    metadata

  Price        Inter               18px           700          22px Product price

  Old Price    Inter               14px           400          18px Struck-through
                                                                    original price

  Button       Inter               15px           600          20px Button labels

  Input        Inter               16px           400          24px Input values and
                                                                    placeholders

  Navigation   Inter               13px           600          18px Bottom navigation
                                                                    labels

### 3.3 Typography Rules

-   Never use Telma for long paragraphs, forms, or dense product
    information.
-   Body text should normally stay at **16px or larger** on mobile.
-   Use weight to create hierarchy before adding more colors.
-   Prices must be visually clear and easy to scan.
-   Avoid all-caps for long text.

## 4. Spacing & Layout

### 4.1 Spacing Scale

Use an **8px base spacing grid**.

  Token          Size Common Use
  ------------ ------ ------------------------------
  `space-1`       4px Tiny icon/text gaps
  `space-2`       8px Inline gaps, compact padding
  `space-3`      12px Small component spacing
  `space-4`      16px Standard padding/gaps
  `space-5`      20px Card internal spacing
  `space-6`      24px Section spacing
  `space-8`      32px Large section spacing
  `space-10`     40px Major layout separation
  `space-12`     48px Hero/section separation
  `space-16`     64px Large page transitions

### 4.2 Mobile Layout

**Smallest target width:** 320px.

Recommended content padding:

-   16px left/right on phones
-   20px on wider phones
-   24px when sufficient space exists

### 4.3 Grid

For the customer storefront:

-   **320--479px:** 2-column product grid
-   **480--767px:** 2-column product grid with wider card spacing
-   **768px+:** 3--4 columns depending on available width

For admin mobile screens:

-   Prefer **single-column forms**
-   Use horizontal scrolling only for compact data tables when
    unavoidable
-   Prioritize cards/list rows over desktop-style dense tables

### 4.4 Corner Radius

  Element                            Radius
  ---------------------- ------------------
  Small controls                       10px
  Inputs                               12px
  Buttons                              12px
  Product cards                        16px
  Large cards/surfaces                 20px
  Bottom sheets            24px top corners
  Pills/badges                        999px

### 4.5 Shadows

Use shadows lightly:

-   Card: `0 2px 12px rgba(32,33,36,0.06)`
-   Elevated modal/sheet: `0 8px 30px rgba(32,33,36,0.12)`

Avoid heavy shadows around every component.

## 5. Component Library

## 5.1 Buttons

### Primary Button

-   Background: Primary `#A2CB8B`
-   Text: Neutral 900
-   Height: 48px
-   Radius: 12px
-   Horizontal padding: 20px
-   Font: Inter 15px / 600

**States:** - Default: Primary background - Pressed: Slightly darker
primary tone + scale/opacity feedback - Disabled: Neutral 300
background + Neutral 500 text - Loading: Keep size fixed and show
spinner

**Examples:** - Add to Cart - Buy Now - Place Order - Save Product -
Create Product

### Secondary Button

-   White or transparent background
-   Border: 1px solid Primary
-   Text: Primary / Neutral 900
-   Same height and radius as primary

**States:** - Default - Pressed: Soft Primary-tinted background -
Disabled: Neutral 100 background + Neutral 500 text

### Destructive Button

-   Background: Error `#C00707`
-   White text
-   Use only for destructive actions such as deleting/deactivating where
    appropriate

### Text Button

-   No background
-   Strong text contrast
-   Used for low-priority actions such as "View All" or "Cancel"

------------------------------------------------------------------------

## 5.2 Inputs

### Standard Text Input

-   Height: 48px
-   Padding: 12px 14px
-   Radius: 12px
-   Border: 1px Neutral 300
-   Font: Inter 16px

**States:** - Default - Focus: 2px accessible focus ring using Primary -
Filled - Error: Error border + error message - Disabled: Neutral 100
background

### Search Input

-   Height: 48px
-   Leading search icon
-   Clear action when text is present
-   Placeholder example: `Search products...`

### Select

-   Same height and border system as text input
-   Trailing chevron
-   Clear selected-value state

``` text
│ ₹399   ₹499          │
│ ★★★★★ (124)         │

```

### Rules

-   Image area uses a consistent aspect ratio, ideally 1:1.
-   Wishlist icon sits in the top-right area.
-   Product name supports up to 2 lines.
-   Discounted price receives stronger emphasis.
-   Original price is smaller and struck through.
-   Rating is secondary information.
-   Add to Cart is available directly when practical.

## 5.6 Modals & Bottom Sheets

### Modal

Use for:

-   Delete/deactivate confirmation
-   Small decisions requiring attention

Structure:

``` text
Title
Supporting message
[Cancel] [Confirm]
```

### Bottom Sheet

Use on mobile for:

-   Filters
-   Sort
-   Variant selection
-   Quick actions

Rules:

-   Top corners: 24px
-   Clear drag/close affordance
-   Primary action remains visible
-   Background page is dimmed
-   Tapping outside closes only when the action is non-destructive

## 7. States

## 7.1 Loading

### General

Use skeleton placeholders rather than large blank areas.

Examples:

``` text
[Logo]   [○] [○]

████████████████████
████████████████

████████  ████████
████████  ████████
```

Rules:

-   Keep layout stable while loading.
-   Avoid unnecessary full-screen spinners.
-   Use a spinner for short action-based loading such as saving a form.

## 7.3 Error

### General Error

Show:

-   Friendly title
-   One-sentence explanation
-   Retry button
-   Back/Home option

### Form Error

-   Highlight the incorrect field
-   Show short text directly below the field
-   Preserve the user's other entered values

### Payment Error

Show:

-   Payment failed/cancelled message
-   Retry Payment
-   Return to Cart
-   Contact/support path when necessary

Never show technical server details to customers.

------------------------------------------------------------------------

## 7.4 Success

Success feedback should be immediate and specific.

Examples:

-   Product added to cart → small confirmation banner/toast
-   Wishlist saved → heart fills + short confirmation
-   Product saved in admin → success message + return to list
-   Order placed → dedicated confirmation screen
-   Discount created → success message + discount list

## 8. Accessibility

### 8.1 Contrast

-   Body text must meet **WCAG (Web Content Accessibility Guidelines)
    2.2 AA** contrast targets wherever practical.
-   Do not use Primary, Secondary, Warning, or Error color as the only
    way to communicate meaning.
-   Error messages should include text and, where useful, an icon.

### 8.2 Touch Targets

-   Minimum interactive target: **44 × 44px**
-   Primary mobile buttons: approximately **48px** high
-   Keep icons separated enough to prevent accidental taps.

### 8.3 Font Legibility

-   Body text: 16px minimum for most customer-facing content.
-   Maintain adequate line height.
-   Do not place long body text in Telma.
-   Support browser/device text scaling without breaking layout.

### 8.4 Keyboard Accessibility

For larger-screen/web contexts and admin screens:

-   All interactive elements must be keyboard reachable.
-   Focus order must follow visual order.
-   Focus indicators must remain visible.
-   Do not trap focus in a modal without a clear close path.

### 8.5 Screen Readers

-   Use semantic headings in logical order.
-   Buttons should describe their action.
-   Icon-only controls must have accessible labels, for example:
    -   "Add to wishlist"
    -   "Remove from wishlist"
    -   "Open cart"
-   Form inputs need visible labels or accessible equivalent labels.
-   Status messages should be announced appropriately where possible.

### 8.6 Motion

-   Keep animation subtle and short.
-   Do not rely on animation to communicate essential information.
-   Respect reduced-motion settings where supported.

------------------------------------------------------------------------

## 9. Responsive Expansion

Although V1 is mobile-first, the design system should scale to larger
screens.

### Desktop Changes

-   Header can expand into full navigation.
-   Product grid can increase to 3--4 columns.
-   Checkout can become a two-column layout:
    -   Left: customer/delivery information
    -   Right: sticky order summary
-   Admin can use a permanent sidebar.
-   Modals can be centered instead of bottom sheets where appropriate.

The same components, typography hierarchy, colors, and spacing tokens
should remain consistent.

## 11. V1 Design Principle

**Dearr should feel like a warm gift shop first and a technical
e-commerce system second.**

The interface should make the customer feel comfortable discovering,
saving, and buying products while keeping the founder's management
screens simple enough to use every day.
